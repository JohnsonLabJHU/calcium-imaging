📖 How to use this tool — read me first

This tool does two jobs in one pass: it stores your calcium movies in the lab cloud (durable, searchable, backed up) and runs the full GCaMP analysis on the GPU platform — Suite2p registration and ROI detection, then the trained ROI + spike classifiers, event kinetics, and neuron grouping. You never attach anything in eLabFTW by hand, and you don't need the separate image-upload tool — uploading here archives the data for you too.

A · Step by step

  1. Pick the experiment (Step 1). Click the box to browse a dropdown of every experiment, or type part of the title or the #id to filter. Completed studies are hidden unless you tick "include completed studies."
  2. Add your recordings (Step 2). First pick the Preparation: In vitro (culture — no animal/eye) or In vivo (animal). Then add individual movie files + their snap stills, or pick a whole folder — nested structure is fine and movies are paired with their snaps automatically (rec1.tif ↔ rec1_snap.tif, TIFF only). In vitro: recording IDs come from the file/folder path and region/timepoint/treatment are optional — nothing per-file is required, which keeps bulk uploads quick. In vivo: Animal ID is required and each movie is renamed to animal_eye_region_timepoint_treatment_date_NN. Movies are archived to the lab cloud (leave "Save to the lab image archive" ticked). Option B: to re-analyze movies already uploaded to this experiment, skip the file pickers and tick them in "Use movies already in this experiment" — no re-uploading, and snaps are matched from the archive automatically. A movie with no snap still runs — Suite2p uses its own ROI detector instead of Cellpose for that recording.
  3. Set the Suite2p options (Step 3) — usually leave the defaults; set fs to your true acquisition frame rate.
  4. Set the analysis options (Step 4). Pick the model pair that matches how the data were acquired and the sensor you used; leave grouping on correlation unless you have a reason to change it.
  5. Submit. The run is queued; the GPU platform pulls your movies from the cloud, runs Suite2p then the classifiers, and writes the results back automatically. Nothing else for you to do.
  6. Find your results under "Recent analyses on this experiment" at the bottom. Each run shows its status (Queued → Running → Done). When Done, click Files ▾ to view or download the results right here — a per-recording Excel metrics workbook, correlation/grouping plots, and a portable results bundle — individually or all at once (open still takes you to the full record in eLabFTW). Always glance at the segmentation/QC overlay first.

B · What each setting means (and when to change it)

SettingWhat it doesWhen you'd change it
Settings profileA validated Suite2p configuration bundle (registration + detection defaults).Switch only when a new profile is added for a different acquisition scope.
fs (Hz)Acquisition frame rate. Drives event kinetics and deconvolution.Always set to your recording's true frame rate.
Cellpose modelThe segmentation network applied to the snap still. cpdino_RGC-Snap is fine-tuned on retinal ganglion-cell snaps.Match the model to what your snap looks like; use a retinal model for RGCs.
Diameter (px)Expected cell diameter for Cellpose. Leave blank and Cellpose infers it automatically.Enter a number only if auto-sizing under- or over-segments; measure a few cells in Fiji.
Cell-prob thresholdHow confident a pixel must be to count as part of a cell. Lower = more/larger ROIs. Default 0.0.Lower to recover dim cells; raise to drop faint/background objects.
Flow thresholdStrictness of mask shape (max allowed flow error). Higher = more, looser masks. Default 0.4.Raise toward 0.6 if real cells are missed; lower toward 0.2 for spurious blobs.
# channels / Functional channelAcquisition channel count and which channel carries the GCaMP signal.Set for multi-channel acquisitions.
Model pairWhich trained ROI + spike classifier set is applied — 15 Hz in-vitro vs 3 Hz in-vivo.Match to the acquisition context. Never mix — kinetics are frame-rate- and indicator-specific.
SensorThe GCaMP variant, which sets the expected transient kinetics.Set to the indicator you imaged (e.g. GCaMP6s vs 8s).
GroupingHow co-active neurons are clustered — correlation, weighted correlation, STTC, combined (STTC + correlation), or none.STTC is more robust to firing-rate differences; "combined" uses both together; "none" skips grouping.
Dry-runValidates the inputs and config without running the full analysis.Use to check a batch will parse before committing GPU time.

C · Understanding the output numbers

For each recording the workbook reports per-ROI event metrics (event rate, amplitude, and kinetics) after the trained ROI classifier keeps active cells and the spike classifier keeps real transients, plus neuron grouping / co-activity matrices and plots. Treat detected events as candidate transients, and interpret kinetics in an indicator- and frame-rate-aware way — this is why the model pair and fs must match the acquisition, and why you should never compare across mismatched acquisition contexts. Always glance at the segmentation/QC overlay first: good-looking metrics are meaningless if the ROIs landed on the wrong structures.

References: Pachitariu et al., bioRxiv 061507 (2017) — Suite2p; Stringer et al., Nat Methods 18:100 (2021) — Cellpose; Dombeck et al., Neuron 56:43 (2007) — ΔF/F baseline; Friedrich et al., PLoS Comput Biol 13:e1005423 (2017) — OASIS; Rupprecht et al., Nat Neurosci 24:1324 (2021) — CASCADE.
